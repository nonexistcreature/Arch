# 08 — Тестирование: всё проверяется автоматически

Правило: **красный тест = стоп.** Следующая волна модов, релиз или деплой — только при зелёных
уровнях 1–4. Уровни 5–7 — перед каждым релизом. Результаты — в `docs/reports/test_runs/<дата>.md`.

## Уровень 1. Статика (секунды)

`tools/check_pack.py`:
- `packwiz refresh` без ошибок; у каждого `.pw.toml` есть хеш и верная сторона (`client`/`server`/`both`);
- все обязательные зависимости присутствуют; нет запрещённых пар из таблицы «один мод на категорию»;
- **нет запрещённых модов** (Apotheosis, Apothic Enchanting/Spawners/Attributes и др. из 02 §A) —
  ни напрямую, ни как зависимостей (проверка по slug и по modid внутри jar);
- нет дублирующихся modid (после скачивания в кеш — разбор `META-INF/neoforge.mods.toml` каждого jar);
- клиентские моды не попадают на сервер (по метаданным + список известных client-only);
- у CurseForge-модов нет запрета стороннего скачивания (иначе — `blocked_mods.md`);
- конфликт клавиш в шаблоне `options.txt` = 0 (`tools/check_keybinds.py`);
- паритет ключей `ru_ru.json` / `en_us.json` = 100 %.

## Уровень 2. Запуск сервера (минуты)

`tools/server_boot_test.sh`: свежий каталог, тот же образ/версия NeoForge, что в проде,
тестовый мир (фиксированный сид), `online-mode=false` **только на localhost/изолированной сети**.
Проходит, если:
- `Done (...)!` за ≤ 6 минут, процесс жив ещё 3 минуты;
- `tools/log_scan.py` по `latest.log`/`debug.log` не находит: `Mixin apply failed`,
  `Missing registry`, `Failed to load datapack`, `Couldn't parse data file`, `Exception` вне
  списка известных безвредных (`tests/log_allowlist.txt` — каждое исключение с обоснованием),
  ошибок KubeJS (`logs/kubejs/server.log`), ошибок FTB Quests;
- сервер корректно останавливается по `stop` (мир сохраняется).
Побочный продукт: **дамп реестров** (KubeJS-скрипт при старте пишет все item/block/fluid/entity/
recipe-type/advancement id и теги в `tests/out/registry.json`) — нужен валидаторам.

Бисекция: `tools/bisect_mods.py` — при падении автоматически делит набор модов пополам (с учётом
зависимостей) и находит виновника за log2(N) запусков. Итог — в `docs/reports/conflicts.md`.

## Уровень 3. Данные

- `tools/validate_refs.py`: все id в KubeJS-рецептах, тегах, лут-таблицах, конфигах (где есть id),
  теги `#arkhaven:rift_spawns`, `#arkhaven:ward_fuel/*` — существуют в `registry.json`.
- `tools/validate_quests.py`: см. `04_QUESTS.md` §7.
- `tools/handshake_report.py`: таблица рукопожатий из комментариев `// HANDSHAKE:`; у каждого
  есть соло-обход (рецепт-альтернатива) — иначе предупреждение.
- Рецепты не дублируются с конфликтом (одинаковый ввод → разный вывод) — по дампу рецептов.

## Уровень 4. Сценарии на сервере (RCON)

- **GameTests мода arkhaven-core** — в его dev-окружении (`./gradlew runGameTestServer`).
- **Интеграционные сценарии** на полном сервере: `tests/scenarios/*.py` подключаются по RCON,
  выполняют команды и проверяют результат (`/execute if block`, `/data get`, `/arkhaven status`):
  1. Оберег + метеорит: построить тест-площадку командами, включить оберег с топливом,
     `/arkhaven event METEOR_STRIKE` над ней и рядом → внутри блоки целы, снаружи кратер с рудой.
  2. Дефлектор Weather2 против торнадо (вызвать командой мода у дефлектора) → блоки целы.
  3. Режиссёр: 0 игроков + `/tick sprint` на 2 игровых часа → ни одного события.
  4. Первое событие типа — учебное; флаг «обучен» ставится при завершении квеста
     (`/ftbquests change_progress` или аналог).
  5. Рукопожатия: для 5–10 ключевых рецептов — выдать ингредиенты фейковому игроку/в машину
     и проверить выход (где реально автоматизировать; остальное — проверка рецепта в дампе).
  6. Сезонный праздник: смена сезона командой Serene Seasons → глава праздника открылась.
  7. **Зоны опасности:** ночь + `/tick sprint` + тестовые игроки в Гавани и в привате →
     естественных враждебных мобов 0; в зоне 2 — спаун есть; под Мегафакелом — 0;
     босс не появляется на поверхности; взрыв крипера не ломает блоки.
  8. **Расы и классы:** все расы `arkhaven_origins` загружаются без ошибок (лог NeoOrigins),
     способность каждой расы срабатывает (команда выдачи/применения); деревья Pufferfish
     загружаются без ошибок датапака; тег умения меняет поведение (например, длительность еды).
  9. **Алхимия:** каждое своё зелье варится по рецепту и даёт нужный эффект; у каждого
     дебаффа из таблицы 10 §4 есть минимум два противоядия (проверка по данным).

## Уровень 5. Клиент (HeadlessMC + Xvfb + Mesa llvmpipe)

- Используй **HeadlessMC** (и/или GitHub Action **mc-runtime-test** для NeoForge): запуск полного
  клиентского набора модов (как его ставит packwiz-installer со стороной `client`), под Xvfb
  с программным рендером. Офлайн-аккаунт — только для локальных тестов и только против
  тестового сервера в изолированной сети (у владельца есть лицензия; к публичным серверам не
  подключаться).
- Проходит, если: главное меню FancyMenu открылось; одиночный тестовый мир загрузился;
  клиент подключился к локальному тестовому серверу и провёл там ≥ 5 минут; нет краша;
  в логе нет ошибок загрузки ресурсов/шейдеров сверх allowlist.
- **Скриншоты** (через команды HeadlessMC/hmc-specifics или клавишу F2 по сценарию):
  титульный экран, экран загрузки, игровой HUD в 1920×1080 (GUI 2 и 3) и 1366×768 (GUI 2),
  квестовая книга (глава 0), EMI, инвентарь, Jade-подсказка, экран настроек.
  Проверки: `tools/screenshot_checks.py` — доля «фиолетово-чёрных» пикселей (нет текстуры) ≈ 0,
  кириллица отрисовалась (нет квадратиков — сравнение с эталоном шрифта); затем **агент сам
  смотрит скриншоты** на наложения HUD, обрезанный текст, кривые окна.
- Шейдеры в llvmpipe: один запуск на пресет «Красиво» — только проверка, что шейдер
  компилируется без ошибок (лог Iris) и делается хотя бы один кадр. FPS здесь не мерить.

## Уровень 6. Нагрузка (перед релизом)

- Тестовый мир `tests/worlds/bench/` (готовится агентом командами/схематиками): крупная фабрика
  Create, сеть AE2, работающий реактор Mekanism, колония MineColonies на ~20 жителей, 2–3 собранных
  корабля Aeronautics, ферма животных, грядки.
- 5–8 ботов-клиентов HeadlessMC (офлайн, изолированная сеть): разлетаются, генерируют чанки,
  один летает на корабле (если управление можно заскриптовать; иначе — телепорт рядом с
  движущимся кораблём), остальные стоят на базах.
- Метрики: spark `/spark tps`, `/spark profiler --timeout 300`. Цели: среднее MSPT < 35 мс,
  p95 < 50 мс, нет утечки памяти за 60 мин (heap после GC не растёт > 10 %).
- Если не проходит: по профилю найти топ-потребителей, настроить конфиги (кап мобов, лимиты Sable,
  частота тиков машин, MineColonies), повторить. Итог → `docs/reports/performance.md`.
- **FPS на реальной видеокарте** в CI не измерить: подготовь чек-лист для владельца в
  `HANDOFF.md` (2 минуты: пройтись по Гавани и базе с `/sparkc profiler`, прислать ссылку),
  и пресеты подстраиваются по присланным данным.

## Уровень 7. Релиз и инфраструктура

- **Апгрейд мира:** мир, созданный на прошлой версии сборки, грузится на новой без
  `Missing registry entries` и потерь (сравнить ключевые блоки/сущности тестовой базы).
- **Бэкап/откат:** сделать снимок, сломать тестовый мир, откатить скриптом, проверить.
- **Установщик:** на `windows-latest` (GitHub Actions) или вручную в Windows-VM: тихая установка
  (`/VERYSILENT`), файлы на месте, ярлыки созданы, pre-launch packwiz-installer на Windows
  скачал все моды и хеши сходятся, деинсталляция чистая.
- **Внешний доступ:** подключение к боевому серверу извне домашней сети (DNS-имя/playit),
  UDP голосового чата проходит.

## CI (если владелец дал GitHub)

`.github/workflows/`: на каждый push — уровни 1–3; на PR в `main` — 1–5 (кеш скачанных модов и
`.minecraft`); вручную/по тегу релиза — 6–7 и сборка exe. Без GitHub — те же скрипты локально
(`make test`, `make release`).

# 07 — Доставка игрокам (.exe) и домашний сервер

## Часть 1. Клиент: `Arkhaven-Setup.exe`

### Что получает игрок
1. Скачивает `Arkhaven-Setup.exe`, запускает (права администратора не нужны).
2. Выбирает пресет графики (предвыбран по видеокарте) → «Установить».
3. Открывается лаунчер с окном входа Microsoft → вход (единственный ручной шаг).
4. Жмёт «Играть». Первый запуск скачивает моды (~1–1,5 ГБ, окно с прогрессом),
   игра стартует и **сразу подключается к серверу**. Дальше обновления приходят сами.

### Устройство
- **Prism Launcher (portable, Windows x64)** — без модификаций бинарников (GPL-3.0: положить
  лицензию и ссылку на исходники в папку установки). Экземпляр **Arkhaven** заранее настроен:
  NeoForge 1.21.1 (точная версия), Java 21, память 8 ГБ (или по пресету), JVM-флаги, иконка.
- **Java 21:** встроить Temurin 21 JRE в установщик (надёжнее, чем автозагрузка).
- **Автообновление:** pre-launch команда экземпляра
  `"$INST_JAVA" -jar packwiz-installer-bootstrap.jar -s client <URL>/pack.toml`
  (окно прогресса packwiz-installer оставить видимым). Моды скачиваются с Modrinth/CurseForge,
  а не с наших серверов. Конфиги, которые игрок может менять (графика, клавиши, звук),
  помечаются в packwiz как `preserve = true` — обновления их не затирают.
- **Ярлыки:** «Arkhaven» → `prismlauncher.exe --launch Arkhaven --server <адрес>`
  (проверь актуальные ключи CLI Prism), «Arkhaven — сменить графику» (см. 06 §2),
  «Arkhaven — папка игры» (скриншоты, схематики).
- **Inno Setup**: установка в `%LOCALAPPDATA%\Arkhaven`, деинсталлятор (спрашивает, удалить ли
  скриншоты/схематики/одиночные миры), русский и английский интерфейс установщика.
  Сборка: GitHub Actions `windows-latest` или локально через Wine (`iscc`).
- **SmartScreen:** exe без подписи → Windows покажет предупреждение. В `HANDOFF.md` — инструкция
  «Подробнее → Выполнить в любом случае». Подпись кода — опционально, если владелец захочет.
- Для Mac/Linux: `Arkhaven-prism.zip` (импорт экземпляра в Prism) + `Arkhaven.mrpack` (резерв).
- **Не встраивать jar-файлы модов в установщик** (лицензии авторов) — только автозагрузка.

### Канал обновлений
- Хостинг файлов packwiz (`pack.toml`, `index.toml`, `*.pw.toml`, конфиги, скрипты, квесты):
  **GitHub Pages** (если есть GitHub) — работает, даже когда домашний сервер выключен.
  Иначе — статический HTTPS-сервер (Caddy) на домашнем ПК.
- Версионирование `MAJOR.MINOR.PATCH`. Сервер и клиенты всегда на одной версии (сервер
  берёт тот же `pack.toml` при перезапуске). Обновление сборки **не требует** нового exe.
- Скрипт `tools/release.sh`: тесты → bump версии → changelog (+ квест «Что нового») →
  публикация → перезапуск сервера с объявлением в чате.

## Часть 2. Домашний сервер

### Требования и предпроверка
`server/preflight.sh` (по SSH) собирает: ОС, CPU, ОЗУ, диски, свободное место, Docker,
скорость сети, занятость портов, есть ли UPnP у роутера. Результат → `docs/reports/server_preflight.md`.
Минимум: 32 ГБ ОЗУ (heap 12–14 ГБ), 6+ быстрых ядер, NVMe 250+ ГБ, проводная сеть, отдача ≥ 20 Мбит/с.
Если меньше — понизить нагрузку (дальность, лимиты Sable/MineColonies) и записать компромиссы.

### Платформа
- **Ubuntu Server 24.04 LTS** (рекомендовано). Если на машине Windows и владелец не хочет
  переустанавливать — путь через WSL2 + Docker, задокументировать отдельно.
- Docker Engine + compose plugin; системный пользователь `arkhaven`; каталог `/opt/arkhaven/`
  (`compose/`, `data/`, `backups/`, `scripts/`). Чужие сервисы и настройки не трогать.

### Контейнер (`server/docker-compose.yml`)
Образ `itzg/minecraft-server` (Java 21) — умеет NeoForge и packwiz по URL:
- `TYPE=NEOFORGE`, `VERSION=1.21.1`, `NEOFORGE_VERSION=<закреплённая>`, `PACKWIZ_URL=<URL>/pack.toml`
  (на сервер ставятся только моды со стороной `server`/`both` — проверь `side` в каждом `.pw.toml`);
- память 12–14 ГБ, G1-флаги для модпаков (Aikar) — альтернативу (Generational ZGC) сравнить
  в фазе производительности по spark и выбрать лучшую;
- `ONLINE_MODE=true`, `ENABLE_WHITELIST=true`, `WHITELIST`/`OPS` из `00_USER_INPUTS.md`,
  `DIFFICULTY=normal`, `VIEW_DISTANCE=10`, `SIMULATION_DISTANCE=6`, `SPAWN_PROTECTION=0`,
  `MOTD`, иконка сервера, `ENABLE_RCON=true` (пароль в `.env`, порт только на localhost);
- порты: `25565/tcp` (игра), `24454/udp` (Simple Voice Chat);
- `restart: unless-stopped`, healthcheck, ротация логов.
- Серверные конфиги для новых миров — `defaultconfigs/`; правила игры — через datapack/команды
  при первом старте (сон 34%, фантомы выкл., граница мира).

### Доступ друзей извне (по порядку предпочтения)
1. **Проброс портов** на роутере (вручную по инструкции владельцу или автоматически через UPnP,
   если роутер позволяет) + бесплатное динамическое DNS-имя (DuckDNS/своё доменное имя),
   контейнер-обновлятель IP. Адрес вида `arkhaven.duckdns.org`.
2. **playit.gg** — если «серый» IP/CGNAT или нет доступа к роутеру: агент в контейнере/systemd,
   TCP + UDP; владелец один раз привязывает агента к аккаунту по ссылке.
3. Tailscale — только если 1 и 2 невозможны (каждому игроку ставить клиент — неудобно).
В клиент вшивается **DNS-имя**, а не IP, чтобы смена адреса не требовала переустановки.
Проверка доступности извне: тест подключения с внешней точки (например, временный клиент
HeadlessMC в CI или онлайн-проверка порта) — результат в отчёт.

### Обслуживание
- **Бэкапы:** контейнер `itzg/mc-backup` (restic): ежечасно, хранить 24 ч / 7 дней / 4 недели,
  с паузой автосохранения на время снимка. Если есть второй диск/USB — копия туда.
  `server/restore.sh <снимок>` + **проверенный** тестовый откат (развернуть в отдельную папку,
  запустить, убедиться, что мир цел).
- **Ночной рестарт** (по умолчанию 06:00): предупреждения в чат за 5 и 1 минуту, `save-all`, рестарт.
- **Автостарт** после перезагрузки ПК; **сторож**: если healthcheck падает 3 раза — рестарт и запись в лог.
- (опц.) Discord-вебхук: сервер поднят/упал/рестарт/крупное событие.
- Безопасные обновления ОС (unattended-upgrades) — только security; без автоперезагрузки.
- Файрвол: открыть только нужные порты (если используется ufw), RCON — только локально.
- `server/README.md`: старт/стоп/логи/консоль/бэкап/откат/обновление — простыми командами.

### Запуск мира (один раз)
1. Первый старт → мир по выбранному сиду → правила игры → Гавань (NPC, доска) → spawn.
2. Прегенерация Chunky (~3000 блоков) + LOD Distant Horizons → проверка TPS.
3. Нагрузочный тест (08 §4) на копии мира → настройка → боевой запуск.
4. Белый список включён, владелец — OP.
